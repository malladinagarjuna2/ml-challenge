The final zip also contains candidate_pairs.tsv (our blocking shortlist, audited but not scored), the runnable code, and a methodology document. External lookups (geocoding, business registries, APIs) are forbidden. Any model must be MIT/Apache-2.0 licensed and ≤ 8B parameters.

2How we are scored

Macro F0.5: an F-score is calculated separately for each Source 1 entity, then averaged over all of them.

F0.5 = (1.25 × Precision × Recall) / (0.25 × Precision + Recall)

Precision matters twice as much as recall

A wrong match (false merge) hurts about twice as much as a missed one. When unsure, don't match.

Singletons are all-or-nothing

If an entity truly has no matches, an empty prediction scores 1.0 and any prediction scores 0.

Worked example

Predicted [S2-47, S2-193, S3-812], truth [S2-47, S3-812] → precision 2/3, recall 1 → F0.5 = 0.714. The single extra wrong ID cost almost 30% of that entity's score.

What these facts mean

  • "0 records matched twice": each S2/S3 record belongs to at most one S1 entity. If a record is claimed by two S1 entities, at most one of them can be right; we will keep only the best one.
  • 26% decoys: many S2/S3 records look similar to something but match nothing. These are what cause false merges.
  • US and India behave the same: 5.6% singletons and 3.46 matches on average in both, so the data was likely generated the same way. We expect France to follow the same pattern.

5Catalog of the noise we observed

In names

  • Digit typos: C0mpany, 5ecure
  • Random accents: Ínc, Léarning, Àmicale
  • Legal suffix changes: Inc ↔ Incorporated ↔ LP ↔ none
  • Descriptor words added or dropped: Indchem Power = Indchem Services
  • Word order: asset committee building
  • Junk prefixes: -- >> *** # @ <<
  • Aliases (mostly Source 3): dba, formerly, f/k/a, aka, t/a
  • Website instead of a name: about 4% of rows
  • Indian scripts: 9–11% of names
  • Made-up, unrelated names: Vioorbisyn, Quokorflux

In addresses

  • Abbreviations: St / Street / Saint, Rd / Road, Dr / Drive
  • Components reordered: TX, 709 Hackberry…
  • Missing parts; 3.4% fully empty or NULL
  • Zero padding 00709, dropped digits 1344→344, B-259→B-59
  • States as code, full name, or native script: TX/Texas, DL/Delhi/दिल्ली
  • Landmarks: Near Infopark South Gate, Opp SBI ATM
  • India formats: H.No, Door No, KH NO. -570/13, 5-513/4
  • City noise: CHICAGOCDP, Erlanger Ky
  • France (test only): R. = rue, bis, SARL/SAS/EURL/SCI

Design decisions

  • Transliterate, don't translate. anyascii converts every script to Latin offline, so no external service is used. Character n-grams will cover spelling gaps such as marketimg ↔ marketing.
  • Keep several versions of each name. Legal suffixes and descriptor words are sometimes meaningful (Acme Robotics vs Acme Bakery), so the model receives both the full and the stripped versions.
  • Addresses as a bag of components, because vendors reorder them.
  • Nothing hard-coded to US/India. Country tables are only extra rules; an unseen country like France still gets all the generic cleaning.

9What comes next

3 · Blocking (next)

  • Several cheap ways to shortlist candidates, combined: TF-IDF character n-grams on names (top-K neighbours), rare shared name tokens, same house number + postcode/city, phonetic keys
  • Always within the same country
  • Goal: keep ≥ 98% of true pairs with a manageable number of candidates per S1 entity
  • Output: candidate_pairs.tsv

4 · Features

  • Name: Jaro-Winkler, token-set ratio, TF-IDF cosine, best match across aliases, legal-form conflict
  • Address: house-number agree/conflict, postcode, state, street similarity
  • Context: rank of the candidate within its group, gap to the best candidate

5 · Model

  • LightGBM on the pair features, cross-validated by S1 entity
  • Optional upgrade: a fine-tuned multilingual cross-encoder (small, Apache/MIT) whose score is fed in as a feature

6 · Decisions for F0.5

  • Each S2/S3 record goes to at most one S1 entity (from section 3)
  • Per entity, keep only the candidates that maximize expected F0.5; predict empty if nothing is confident
  • Run validate_submission.py, then upload
