Facts from the answers that shaped the design

  • 0 of 7.6M S2/S3 records belong to two S1 entities → a one-to-one rule is safe.
  • 0 of 7.6M links cross countries → everything can be done country by country.
  • About 26% of S2/S3 records match nothing (decoys) → the source of false merges.
  • Some true links have unrelated names (Straight Edge Ice Cream ↔ XYLOQUO) → address-only matching must be possible.

4Blocking: building a shortlist of 40 candidates per business

Comparing 1.7M × 10M records directly is impossible, so each Source 1 record first gets a cheap shortlist.

How it works

  • Compare only inside country + state (no-state records compared against the whole country; Telangana + Andhra merged)
  • 4 TF-IDF views: name 3–4-grams, street 3–4-grams, phonetic 3–4-grams, words 1–2
  • 2 exact keys: house number + street word; rarest name word
  • Rank by reciprocal-rank fusion, keep the top 40

Measured (20k train S1 vs all 10.3M S2/S3)

  • All views together find 98.3% of true matches
  • Top 40 keep 97.7% (US 99.6%, India 96.5%)
  • A 3–5-gram view was dropped: 58% of the time for 0.03% extra matches
  • Speed: 12–50 h estimate → about 11 min for train

5Features and model

82 features per candidate pair

  • Name: ratio, token-set, partial, Jaro-Winkler, Levenshtein, phonetic, rare-word weights, legal-form agreement
  • Address: street similarity, house-number overlap, state and postcode agreement, empty-field flags
  • Blocking: score in each view, fused rank
  • Competition: how this candidate ranks among the business's candidates, and whether another business claims the same record

Two-stage XGBoost on the GPU

  • Stage 1: 82 features, 5 folds grouped by business, about 1,000 trees each (~7 min per fold on the RTX A2000)
  • Stage 2: adds 13 features built from stage-1 scores (support from sibling candidates, reverse competition)
  • Stage-1 AUC 0.9995; stage-2 AUC 0.9996
  • Most useful: combined similarity, fused rank, house-number difference, reverse competition

Training ran on a random sample of 200k training businesses against all 10.3M S2/S3 records. Section 8 explains why this sampling is probably the main weakness.

8Why the score is 0.965 and not 0.99

We lose 0.035. Measured on validation, it splits like this:

With a perfect model on the same shortlist the score would be 0.991, so the shortlist is fine; the model is too cautious.

The model's probability for the 36,820 true matches it rejected

43% of rejected true matches had probability 0.5–0.9. The wrong matches we kept have a median probability of 0.84, so the two groups overlap and the decision rule has to set a high bar.

Probable root cause (hypothesis, not yet proven)

Training used a random 200k of 2.2M businesses, but candidates came from all 10.3M records. Many strong-looking candidates belong to a business that is not in the sample, so in training they appear as "looks like a match, labelled no-match" with nobody competing for them. The model learns to be cautious. At test time every business is present and competes for its own records, so that caution is unnecessary.

Fix: train on all businesses of complete states, and add name-uniqueness features (is "Big Grill" the only one in the country?).

9Errors and bottlenecks (honest list)

Errors

  • Design: random-sample training → over-cautious model
  • Design: no name-uniqueness features
  • Design: France not partitioned
  • Process: models kept only in memory → lost when the kernel locked
  • Process: an inefficient text-ID comparison locked the kernel (would have taken days)
  • Process: 35 min of CPU training wasted before the GPU switch
  • Communication: I went back and forth on whether the DEV score was inflated; the measurement settled it

Bottlenecks (the 6-hour run)

About 2 h of the test inference ran on one CPU core (Python loops) and France took 60 min unpartitioned.

11What comes next (run 2)

Make runs safe and fast

  • Save every stage to runs/runXX/ as soon as it finishes
  • Spread the three single-core loops over 22 cores (~15× faster)
  • Split France by region
  • Target: about 2 hours per full run instead of 6

Raise the score

  • Train on complete states instead of a random sample
  • Add name-uniqueness features for address-less records
  • Test on a small region first (~15 min per experiment); full run only if validation clearly beats 0.965
  • Later: GPU embeddings for Indian-script names (up to +0.009)
